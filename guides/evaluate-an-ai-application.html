Evaluate an AI application

If you cannot fail a build, you are demoing, not evaluating.

Who this is for

You have a prompt, RAG app, or agent and you need a repeatable quality signal.

Short answer

Write a golden set. Prefer automatic checkers (schema, tests, citations). Use LLM-as-a-judge only with a rubric and human spot checks.

Decision tree

  1. If a unit test or parser can decide, do not use a judge model.
  2. If answers must match documents, score retrieval and faithfulness.
  3. If style is the product, use a small human-labeled set plus a judge you calibrated.
  4. If tools can do harm, include security cases (injection, over-reach).

Default

Twenty cases: happy path, missing context, must-refuse, and one regression from a real bug. Run on every prompt or index change.

Alternatives

  • Production traces sampled into the set (watch privacy).
  • Pairwise judging when you are comparing two prompt versions.

Tradeoffs

LLM-as-a-judge scales and can be biased. Golden sets go stale. Human review is slow and still required on a sample.

Steps

  1. Define pass/fail in writing.
  2. Add cases on Prompt Hub Golden Sets and the Evaluation Hub.
  3. Store expected citations or tool traces, not only final prose.
  4. After each change, run the set and record the score next to the git SHA if you have one.
  5. Calibrate any judge against humans before you trust it.
