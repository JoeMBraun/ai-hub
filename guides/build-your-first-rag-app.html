Build your first RAG app

Ground answers in your documents. Expand the RAG Architecture card on the Architecture Hub for the full knowledge unit.

Who this is for

You have documents (policies, tickets, manuals) and you want a chatbot that answers from those documents.

Short answer

Chunk, embed, retrieve, then generate with citations. Do not fine-tune first. Do not skip evaluation.

Decision tree

  1. If the answer must come from your files, continue with RAG.
  2. If there is no corpus, you need a chatbot or an agent, not RAG.
  3. If the model must take actions (send email, edit a ticket), add an agent loop after retrieval — see first agent.
  4. If the whole corpus fits in the prompt every time, skip the vector store until it does not.

Default

One collection, one embedding model, metadata filters for tenant/source, top-k retrieval, answer only from retrieved text, a 20-question golden set.

Alternatives

  • Keyword or hybrid search when names and IDs matter more than paraphrase.
  • Fine-tuning when style must change but facts already live in the model — rare for private facts.

Tradeoffs

When not to use RAG: open-ended brainstorming, tasks with no source of truth, or a corpus you cannot legally index. Fluent answers without retrieval are not “free RAG.”

Steps

  1. Pick 10 real questions and the documents that should answer them.
  2. Read Data Hub chunking cards; start with section-sized chunks.
  3. Index text plus source locators. Isolate tenants.
  4. Prompt: answer only from context; say when context is missing.
  5. Measure citation recall on the golden questions before adding agents.
